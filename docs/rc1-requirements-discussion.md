# DSH 0.1.2-rc.1 适配需求讨论

状态：grill-with-docs 已完成最终确认，to-spec 已发布。本轮未开始代码实现。

Spec：[GitHub Issue #3](https://github.com/marktrue-ahu/dsh-mobile-remote/issues/3)，标签 ready-for-agent；[本地正文](specs/dsh-0.1.2-rc1-compatibility.md)。

## 已确认

- 完整兼容现有插件功能，包括问询和审批。
- 同时支持 DSH 0.1.1-rc.2 与 0.1.2-rc.1。
- 不复用 dsh-std，直接面向 DSH 官方宿主接口评估适配。
- 不盲目升级所有 DSH 依赖包；先核对目标宿主契约及对应包版本。
- 用户对第一轮 Q5 选择了推荐项：可以提供运行环境，目标包括真实宿主验证。具体环境尚待核实；不能据此认定宿主已经可用。
- 完成需求澄清后进入 to-spec，实施前需要用户确认共同理解。
- 当前只修改讨论文档，不自动提交或推送。
- Q6：完整兼容以现有功能逐项通过验证为准。宿主缺陷可以明确报错并保留其他功能，但受影响项仍是验收阻塞；降级不能视作完整兼容完成。
- Q7：保持现有手机 API 和操作语义，现有 App 无需强制更新。
- Q8：在插件内集中管理两版宿主差异，业务路由使用统一能力；只调整受版本差异影响的交互，不全面重构。
- Q9：本次先更新兼容与安装文档，两版实测通过后再按发布流程升正式版本号。
- Q10：已确认 [RC1 兼容验收清单](rc1-acceptance-checklist.md) 的 T01–T19 功能、预期与验证方法；这仅表示测试范围获确认，不代表已执行或通过。
- Q11：两版宿主均覆盖 Desktop 与 Web 形态，并保留 Windows、WSL/Linux 路径回归；缺少环境的项目记录为未验证，不能计入全部通过。

## 流程结果

- 用户已确认最终共同理解，Q1–Q11 需求与验收范围收敛。
- spec 已通过宿主机 GitHub CLI 发布到 origin 对应仓库，包含完整测试清单，已应用 ready-for-agent 标签。
- 本轮交付领域词汇、需求记录、验收清单和 spec；未修改实现代码。用户随后明确授权将这些文档提交并推送到当前适配分支。

## 实施前核实事项

- 核实各目标宿主的实际安装版本、Desktop 对应内核版本、可用环境与服务契约；版本名称和方法名称不能替代运行证据。
- 核实依赖包版本以及图片、余额、推送等用例的测试条件。缺失条件应如实记录，不缩减已确认的验收范围。
- 在 spec 中沿用已确认的测试入口与 T01–T19 清单；不将模拟测试、脚本正常退出或功能降级视作真实宿主通过。

## 澄清记录

- 之前把第一轮 Q5 总结成“没有 RC1 实例时先做静态与启动级验证”不准确。静态验证不能替代用户选择的真实宿主验收。
- 不复用 dsh-std 不代表已确认插件内具体架构，也不意味着删除旧宿主支持。
