# 完整兼容 DSH 0.1.2-rc.1，并保留 0.1.1-rc.2 支持

## 问题陈述

当前移动控制插件的基线为 3.1.1，其宿主适配基线是 DSH 0.1.1-rc.2。用户升级到 0.1.2-rc.1 后，宿主远程调用、会话控制和交互事件契约的变化可能导致模型目录、消息、队列、问询和审批等能力失效。仅验证能安装或普通聊天成功，不能证明移动控制面完整可用。

用户要求同一个插件版本支持两个宿主版本，继续使用现有 Android App，并避免在业务路由中分散维护版本判断。本需求已通过 grill-with-docs 完成确认。

本文中“宿主”指承载会话与 Agent 的 DSH 实例；“移动控制面”指手机可使用的现有控制能力；“完整兼容验收”指约定环境中的既有功能逐项通过验证，降级功能仍属于验收阻塞。

## 解决方案

在插件内部集中处理两版官方宿主的差异，向现有移动控制面提供一致的行为。用户升级宿主和插件后，无需强制更新 App，仍能发送文本与图片、查看历史与运行状态、管理会话和模型、处理问询及审批，并使用其他现有功能。

同时验证 DSH 0.1.1-rc.2 和 0.1.2-rc.1 的 Desktop、Web 形态。宿主缺陷或能力缺失应明确报告并保留其他可用功能，但不能因此宣称已完成完整兼容。

## 实施决策

- **双版本支持**：目标是 DSH 0.1.1-rc.2 与 0.1.2-rc.1，不能通过停止支持旧宿主来完成本需求。
- **适配归属**：不复用 dsh-std，不创建共享兼容框架。两版官方宿主差异集中在插件内；业务路由使用统一能力，只调整受版本变化影响的交互，不进行无关全面重构。
- **对外契约**：保持现有手机 HTTP API、SSE 和操作语义；对两版宿主请求、结果、错误和事件进行必要转换。不得要求强制升级 App。
- **涉及模块**：宿主交互适配、受影响的移动接口调用、实时事件桥、问询和审批应答、桌面设置页集成、诊断，以及相关兼容和安装文档。
- **协议核实**：实施时以对应发布包和固定版本源码核实方法、参数、身份解析、事件及应答契约。不能仅替换点号/斜杠或依据方法名假设语义相同；每项映射须由行为测试验证。
- **依赖处理**：先核对宿主契约和实际存在的依赖包版本，不把所有 DSH 包机械改成同一个版本号。
- **发送和应答**：保留既有回执与重复请求处理语义；对超时或业务拒绝不能盲目切换协议再发一次。问询和审批保持正确的会话归属及一次结算行为。
- **故障边界**：宿主缺陷或能力缺失可以明确报错并保留其他功能。受影响的既有功能仍阻塞完整兼容验收，不能以默认空列表、假成功或“已降级”代替通过。
- **文档与版本**：先更新兼容和安装文档，两个宿主版本实测通过后再进入正式版本发布流程。本任务不自动提交或推送代码。
- **存储约束**：没有批准另行开展会话或插件数据格式迁移；优先保持已有历史、持存队列、回执及配置行为。若核实契约后发现必须改变用户可见行为或数据格式，应明确其影响后重新确认范围。

## 测试决策

用户已确认以下测试入口和功能清单。主要自动化入口是现有手机 HTTP API 与 SSE；真实 Android App 和电脑设置页补充界面验收。检查外部结果与用户语义，不以私有函数名称、调用次数或映射字符串存在作为功能通过依据。

现有测试参考包括：消息与 SSE 联通脚本 e2e-check.mjs、发送回执与重复请求检查脚本、图片格式和载荷限制检查脚本、WSL 路径检查，以及 App 的 API、目录和链接处理测试。联通脚本目前主要打印结果，会向第一个 Agent 发送消息并触发限流；它没有覆盖全部行为或完整失败退出判定，不能直接充当本需求的验收套件。

### 验证方法

- 以现有手机 HTTP API 和 SSE 为主要自动化测试入口，同一套行为断言分别验证 DSH 0.1.1-rc.2 和 0.1.2-rc.1。
- 以现有发布版 Android App 验证用户操作、图片显示、问询审批和重连；电脑设置页另做真实界面验证。
- 模拟宿主或外部服务用于可重复的超时、错误和竞争测试，不能替代真实宿主验收。
- 使用独立测试 profile、临时工作区及专用会话。测试会发送消息、修改配置和创建文件；不直接复用用户正在工作的会话。
- 每个用例记录版本、环境、步骤、预期、实际结果及证据。状态区分通过、失败、未验证和阻塞；跳过不计为通过。

### 外部条件

- 视觉模型、余额接口和第三方推送需要对应测试条件；缺少条件时标记未验证或阻塞，不能用模拟结果宣称真实链路已通过。
- 推送自动化先使用本地接收端验证协议与内容；向真实外部渠道投递前确认专用测试目标。
- 本次验证当前分支的已有功能；其他功能分支中新加的能力不自动纳入本清单。


### 完成判定

- T01–T19 中的功能按实际行为拆分用例，记录到对应宿主环境；两个版本的适用用例均通过后才满足完整兼容验收。
- 现有发布版 Android App 完成关键操作验证，不能只以 HTTP 响应成功代替用户链路成功。
- 宿主缺陷、缺失环境及外部测试条件不足必须列出受影响用例和证据，不得把未执行、跳过或降级计为通过。
- 仅在具备上述证据后更新为“已验证兼容”的发布说明。适配实现完成与完整兼容验收通过必须分开报告。

## 范围之外

- 引入 dsh-std 或推动其成为本插件的依赖。
- 创建供多个插件使用的通用兼容包。
- 强制升级 App、改变现有手机操作语义或无关业务重构。
- 在本任务中维护修改后的 DSH 内核或以绕过审批等方式掩盖宿主缺陷。
- 新增当前基线不存在的功能；其他功能分支中新功能不自动纳入。
- 承诺所有未来 DSH 版本、所有 Android 机型、iOS，或全部操作系统与宿主形态的组合。
- 本轮 spec 交付中的代码实现、正式版本发布、自动代码提交或推送。
