# 0029 手机端工作步骤展示四档语义（v4）

状态：已接受（2026-11-16），设计审定见 GitLab #108 note 2755；实现追踪 #108。关联：ADR 0027（轮次过程与轮末产出物）、ADR 0028（过程折叠视觉）、issue #104（简洁运行中折叠）、#108（四档语义重规范）。

> 2026-11-19：本 ADR §2/§3/§5/§6 的“完全展开当前轮自动展开详情”“50 行分批仍生效”“活动条”由 **ADR 0035** 修订：四档结构语义保留，详情一律手动，取消分批，删除活动条。§6 的“长工具结果裁剪 + 查看全文”仍有效，并由 ADR 0035 补充固定高度上限。

## 背景

ADR 0027 定义了「简洁 / 标准 / 详细 / 完全展开」四档，并与桌面 `presentation-policy.js` 的策略表同构；ADR 0028 进一步约束过程区视觉，并明确「完全展开只影响整轮/过程组可见性，单张工具卡仍默认收起」。

后续 #104 修正了简洁档「运行中强制展开」的问题，但设置页文案、四档实际密度、以及两个旧设置（`showReasoning`、`reasoningDefaultExpanded`）开始互相冲突：

- 「标准」在运行中带组抬头，视觉上比「详细」的平铺行更重，档位名与信息密度相反；
- 「完全展开」实际只展开结构，不展开思考正文/工具卡详情，名不副实；
- 旧的「思考内容」「思维链默认展开」是旧版 DSH 的全局开关，会覆盖四档语义；
- 历史轮全部详情自动展开会造成首屏性能与滚动问题。

#108 经过术语对齐、行为矩阵和 v4 设计稿审定，决定重规范四档语义。

## 决策

### 1. 术语与层级

统一使用 CONTEXT.md 的术语：

```text
轮次 → 过程段 → 过程组 / 过程段摘要 → 过程行（思考行 / 工具过程行）
工具过程行 → 工具卡 → 工具卡详情（参数区 / 结果区）
```

不再使用「轮次卡」等混淆叫法。

### 2. 运行中（当前轮）

| 组件 | 简洁 | 标准 | 详细 | 完全展开 |
|---|---|---|---|---|
| 过程段 | 摘要一行 | 展开 | 展开 | 展开 |
| 过程组 | 不显示；手动展开后组默认展开 | **组抬头可见、组折叠** | **组抬头展开 + 行摘要** | **不分组/平铺** |
| 过程行 | 不显示；手动展开后显示行摘要 | 组折叠时不可见 | 显示行摘要/思考首行 | 显示行摘要 |
| 行详情（思考正文/工具卡详情） | 收起 | 收起 | 收起 | **仅当前轮自动展开**；历史/已完成收起 |
| 活动条 | **隐藏**（摘要承载状态/进度） | 行不可见，显示当前状态 | 仅当前行不可见/不足时显示，去重 | 同详细 |

- 标准档的「组折叠」指只显示过程组抬头，不显示组内过程行；因为行不可见，活动条必须继续表达当前工具/思考。
- 详细档的「组展开」指组抬头展开，组内行摘要可见；工具卡详情、思考正文仍收起。
- 完全展开档不分组；当前轮所有思考正文/工具卡详情自动展开，长结果裁剪并提供「查看全文」。
- 完全展开的详情**只服务当前运行轮**；上一轮/已完成轮的过程行、回答、页脚保持可见，但不自动展开详情。
- 简洁档手动展开摘要后，过程组默认展开（手动优先），一次点击即可看到组抬头 + 行；详情仍收起。

### 3. 已完成（正常回答后）

| 组件 | 简洁 | 标准 | 详细 | 完全展开 |
|---|---|---|---|---|
| 过程段 | 整轮一行 | 整轮一行 | 段展开 | 段展开 |
| 过程组 | 不显示 | 不显示 | 组抬头折叠 | 不分组/平铺 |
| 过程行/摘要 | 不显示 | 不显示 | 组展开后显示行摘要 | 显示行摘要 |
| 行详情 | 收起 | 收起 | 收起 | 收起（手动可开） |

- 「回答结束后」默认立即收起；「下次新消息时」保持段展开，直到下一条真人消息到达后再折叠。
- 异常结束（`aborted`/`interrupted`/`error`）与轮内插话：过程段强制展开；组按档位/手动状态；**详情不自动展开**。
- 50 行分批（「显示更多」）仍生效；任何档位都不能绕过。

### 4. 手动与覆盖优先级

- **手动展开/收起 > 档位默认**；新事件/工具 result 不抢回手动状态；切轮、离开会话、重建后复位。
- 完全展开的自动详情在轮次结束后回到摘要；用户手动展开的详情优先保留到手动收起/切轮。
- 活动条与可见行去重：对应过程行已在视口内且贴底时，不再重复显示同一工具/思考。

### 5. 旧设置

隐藏设置页的：

- 「思考内容」（`showReasoning`）
- 「思维链默认展开」（`reasoningDefaultExpanded`）

两个旧 SharedPreferences key 保留但不读取、不迁移、不参与 UI/行为；升级不报错。思考行默认折叠，仅在完全展开-运行中或手动操作时展开正文。

四档设置说明同步为：

- 简洁：已完成轮折叠成一行；运行中只显示过程段摘要（含状态/进度），活动条隐藏。
- 标准：已完成轮折叠成一行；运行中过程组收起、只显示组抬头，详情收起（默认）。
- 详细：已完成轮展开过程段、组抬头折叠；运行中组抬头展开、行摘要、详情收起。
- 完全展开：运行中当前轮不分组、详情自动展开；已完成轮行摘要、详情收起。

### 6. 性能与安全边界

- 完全展开不自动展开历史/已完成轮详情；避免打开老会话时一次性渲染大量日志。
- 长工具结果使用裁剪 +「查看全文」；不把完整结果直接铺进时间线。
- 50 行分批、图片入口、失败 chip 语义保持。
- 旧宿主/SSE/历史无过程数据时回退普通事件卡；历史回放与实时同口径。
- 320/深色/1.5× 大字号不得溢出；大字号页脚允许两行，保证完成/中止状态不被截断。

## 对既有 ADR 的修订

- **ADR 0027 §2 四档策略表**由本 ADR 取代：标准档从「组抬头展开 + 行可见」改为「组抬头可见、组折叠」；详细档改为「组抬头展开 + 行摘要」；完全展开档增加「当前轮详情自动展开」，且保持不分组。
- **ADR 0028 「完全展开只影响整轮/过程组可见性，工具卡仍默认收起」**由本 ADR 修订：完全展开档在运行中的当前轮自动展开工具卡详情/思考正文；已完成轮仍默认收起详情。
- ADR 0028 的过程区视觉规范（方案 C、导轨、单卡形态、陷阱）继续有效，仅四档语义与详情自动展开规则按本 ADR 调整。

## 被否方案

1. **v3：标准=不分组平铺、详细=组展开**  
   被否：标准仍比详细更“重”，用户审图指出层级相反。
2. **完全展开自动展开所有历史轮详情**  
   被否：首屏渲染、内存、滚动稳定性和老会话性能不可接受。
3. **保留「思考内容」「思维链默认展开」**  
   被否：与四档语义冲突，用户无法判断当前展开由哪个开关控制。
4. **只换图/文案，不换语义**  
   被否：会出现名不副实的设计稿与实现偏差。

## 后果与验收

- `TurnFoldPolicy` 需要从四个布尔扩展为「运行中结构 / 已完成结构 / 行详情自动展开 / 活动条状态」维度，不能靠现有字段硬拼。
- 实现必须覆盖：四档 × 运行中/已完成 × 组/行/详情 × 手动状态 × 插话/异常 × 历史/SSE × 320/深色/1.5×。
- 设置页删除两行并保留旧 key 兼容；i18n 与四档说明同步。
- 设计审定：`/tmp/issue108-design/v4/`（39 张，abyss 浅/深 + DSH 对照），issue #108 note 2755。
- 真机验收：四档各跑一轮含思考 + 多工具 + 插话/中止的会话，检查组折叠、活动条、当前轮详情、轮末收起、50 行分批、旧值兼容。
