# 0021 App 安装包的落位、分发与匿名边界

状态：已接受。背景与验收见 GitLab `ahedu/dsh-mobile-remote#35`。与 ADR 0020（载体分发形态）、ADR 0019（三条判据）配套。

## 问题

APK 随插件到了宿主之后，还需要回答四个问题：**放在哪、谁来写、手机怎么取、未配口令怎么办**。这四个问题任何一个含糊，都会演变成「文件被覆盖」「取到错版本」「匿名接口顺手放行了控制面」这类事故。

## 决策

### 1. 只有两个明确位置

- **人工区**：用户在更新目录里手工放置的产物；宿主**永不自动改写或清理**。
- **托管区**：宿主自管的子目录，内含不可变对象（按对象哈希寻址）、按发布身份的记录、按 profile 的当前指针、与事务绑定的租约、不参与服务的暂存区。写入遵循「暂存 → 校验 → 发布不可变对象 → 原子 rename → 最后原子更新 profile 指针」，禁止原地覆盖已发布 inode；硬链接只从核验过的只读源建立，跨文件系统或不支持时回退复制，**绝不移动源文件**；人工导入一律复制为独立 inode。
- 未配置更新目录时启用一个明确默认目录；所有权标记缺失或布局版本未知时**不接管**并给出诊断，不递归清理。

### 2. 宿主不自取

不由宿主按清单里的 App 地址从网络下载 APK，也不对自身的 APK 路由发起自取请求。APK 到达宿主只有两条路：**随插件安装的载体**（ADR 0020）或**人工放置**。这样失败面收敛为「包管理器跳过了载体」与「用户没放文件」两种，都可诊断。

### 3. 两端一致性靠闸门，不靠回退 App

**Android 不允许降级安装**（系统安装器，无 `INSTALL_ALLOW_DOWNGRADE`）。所以「插件回滚时把 App 也退回去」在手机上根本执行不了，只能在「用户尚未安装新 App」的窗口内生效——而那个窗口已经被「插件未确认 → App 不会先装」的闸门挡住。

因此：一致性由**源头阻挡**保证，App 在下载前与拉起安装器前都要复核固定快照、运行内容标识、健康结果与在飞/回滚矛盾；插件回滚后当前入口按**已恢复实例的内容标识**重新选择旧发布，缺旧 APK 时明确不可用，不让新版冒充。

### 4. 匿名边界与口令

- **唯一匿名例外**是精确匹配的 APK 下载路由（当前配对入口与固定目标）；会话、消息、审批、文件、清单、诊断、插件 tgz 与更新写接口一律鉴权。不能因为 URL 含 `update` 就豁免整个前缀。
- 口令未配置时**fail-closed**：移动控制接口返回「认证未配置」并拒绝，不再解释为关闭认证。这是对既有默认姿态的**破坏性变更**，必须写迁移说明。
- 口令为空时由宿主生成强随机值存入插件状态（**不写用户配置**），本机特权入口把它下发到连接二维码——用户重扫一次即可，不需要理解「口令」这个概念。
- 不引入下载票据：首装浏览器带不了自定义认证头，票据反而引入分发与过期管理；匿名 + 精确路由 + 独立资源配额更简单。
- 匿名下载不是「仅局域网」保证：端口对公网可达时安装包也公开可取。它不授予控制权限，也不得携带口令或个人配置。

### 5. 保留与回收

当前发布不因时间删除；旧发布被替代后按 profile 与**真实选用周期**保留 24 小时（重启或重复请求不重置时钟）；有效事务引用与已打开响应句柄保护的对象不删；GC 汇总所有 profile 取保护并集，并**先核对 profile 存活性**（遗弃指针写墓碑后释放引用）。过期与未就绪用不同状态码区分，过期地址**不重定向到新版**。

### 6. 地址投影不能采信转发头

LAN 桥转发时会删掉 `Host` 并由 HTTP 客户端补成回环地址，若投影直接读 `Host`，手机将拿到 `127.0.0.1`。因此对外地址按**实际本机网卡与监听端口**或显式配置的对外 authority 白名单生成；反向代理只采信显式受信的代理来源与配置的基址；内部 worker 继续使用受信/回环定位，不把手机可达地址写回内部事务。

## 后果

- **破坏性变更**：无口令部署升级后控制面被拒，需重扫二维码一次；必须在升级提示与迁移说明中明示，否则用户会误判为服务故障。
- 需要新增/收紧的测试面：匿名与控制的分流、固定目标不跨快照、过期与未就绪区分、GC 与有效引用的竞争、投影不产生回环地址。
- 匿名下载不保护用户免受网络篡改：生产网络应使用可信渠道（HTTPS/受信代理）或人工核验。

## 替代方案（未采纳）

- **下载票据**：被否（首装无认证上下文；票据引入新的分发、过期与重放管理）。
- **回滚时回退 App**：被否（Android 无法降级安装；且清单回退会让插件再次看到坏版本，可能形成「更新→失败→回滚→再更新」循环）。
- **宿主按清单地址下载 APK**：被否（新增网络下载器与失败面；载体通道已覆盖）。
- **保持「未配口令即关闭认证」**：被否（首装匿名下载与「控制面必须鉴权」无法同时成立；且默认姿态把安全责任推给用户）。
