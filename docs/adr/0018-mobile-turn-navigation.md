# 0018 轮次导航：派生索引、显式三态，且不引入用户标记

状态：已接受。背景与验收见 GitLab `ahedu/dsh-mobile-remote#24`（一期）与 `#25`（二期）。

手机端对话时间线在长会话里缺少按轮次定位的能力：只能一路滚动，用户既不知道当前在第几轮，也不知道一共进行过多少轮。本次新增**轮次导航**——对话页右侧的刻度轨，每轮一个刻度，可预览、可跳转。它是**只读定位**：不改变会话内容或轮次边界，也不产生任何用户标记。

有三件事需要留痕：索引数据从哪来、不可达时怎么说、以及要不要"记住读过哪"。

## 轮次索引是派生数据，且只有一个来源

轮次索引是**轮次号 → 该轮起始事件持久序号**的映射，由会话事件折叠得出。**会话日志里不存在任何用户编写的轮次元数据**——因此它不能被当作"用户数据"来设计持久化或同步。

电脑端本体已经算出这份数据：宿主的**轮次大纲投影**（键 `turnOutline`）给出每轮的轮次号、该轮起始序号、提示词预览与回复预览，电脑端刻度轨直接消费它。二期因此只做**薄适配**把它透出为移动契约，**不在插件里再折叠一遍日志**。

理由是会话语义只能有一个权威来源。仓库既有的「能力语义漂移」风险在这里同样成立：如果插件自己折叠一遍，轮次边界与预览文字的规则就有两份实现，两边迟早在某个边界条件上不一致，而症状是"同一轮在电脑与手机上显示不同"——这类问题不抛异常、只给错答案。

代价是插件依赖一个宿主投影键：宿主未挂载该投影时就没有这份数据。这**不构成拒绝的理由**，但要按既有方针显式报告（见下）。

## 能力状态是三分，且延伸到"会话维度"

宿主不为它的接口声明契约版本，插件只能探测。ADR 0017 已把能力状态从两分（缺失／可用）扩为三分（缺失／**语义漂移**／可用），并确立"不设版本门禁就必须把状态显式报出"。

轮次索引把这一条推进到**一个新维度**：除了"能力在不在"，还有"**这个会话有没有**"。实测中投影缓存里 89/359 个会话没有大纲行，而其中 83 个只有 13 个投影键（现行为 20–24 个）、修改时间密集聚在同一天——它们是**陈旧缓存行**，不是能力缺失。

因此端点必须把三种情况分开表达：**能力缺失**（宿主没挂载投影）／**该会话暂无大纲**／**可用**。**不得**用空数组表达"没有轮次"：那会把"这台电脑不支持"与"这个会话是新的"混成同一个答案，正是 ADR 0017 要消灭的那类静默失败。对陈旧行走一次**强制折叠**（带超时），而不是直接退化成半成品。

移动端据此**先读能力声明再渲染**未加载刻度，不按宿主版本自行推断。

## 有意偏离电脑端，并且不持久化

两处刻意与电脑端不同：

1. **跳转目标不可达时明确说明**。电脑端在历史只剩部分表面、序号不连续时**静默停下**。本仓库反复要求"不可用必须给出明确原因"，静默会让用户以为应用卡住。这是本次唯一有意偏离电脑端行为的地方。
2. **不持久化任何轮次状态**。电脑端的当前轮、跳转进行中、预览全是内存态，明确不落盘。手机端同样**不记"上次读到的轮次"**：那本质上是另一种"书签"，会以"阅读位置"的名义把用户标记悄悄带进范围。若将来需要，作为独立需求单开。

## Consequences

- 轮次索引与刻度集合必须是**纯函数**（进事件、出刻度），以便在没有界面树的测试里钉死；电脑端与手机端的合并语义（按轮次取并集、升序、两边都有时保留已加载锚点、仅在已加载预览为空时取大纲预览）必须一致。
- 端点的三种能力状态各需**稳定字段或错误码**，并被既有门禁脚本覆盖；测试夹具必须能表达"投影注册表缺失"与"会话缓存陈旧"两种宿主形状，而不是只表达"服务在不在"。
- 陈旧会话的**强制折叠耗时**必须先实测再定策略与超时：最大会话日志为 23.6 MB（zstd、帧拼接格式），冷折叠可能显著慢于读缓存。实测之前不承诺"每次请求都强制折叠"。
- 定位机制受对话页既有结构约束：消息流是带 **`center` 锚点**的滚动视图（偏移 0 是中间占位块，上翻后最小滚动范围为负），且没有逐条定位键、没有固定条目高度。采用"目标轮挂键 + `ensureVisible`"，不自算偏移、不引入第三方定位列表组件。
- **分期本身是决策的一部分**：一期只在 App 侧实施，刻度仅覆盖已加载轮次，因此一期不存在"点了没反应的死刻度"；二期接入大纲后才出现需要先取历史的刻度。一期不改服务端，交付链路因此只需发一次应用。
- 刻度轨**不做用户标记**，也不得演化为标记功能；它不写入任何持久状态。

## Considered Options

- **在插件里自己折叠事件日志**：不依赖宿主投影键，能力自足。但会复制会话语义（轮次边界、预览归一），制造两份实现——正是「能力语义漂移」的成因。拒绝。
- **插件直接读会话日志文件**：绕过宿主服务与既有的格式、压缩、迁移处理。仓库现有历史读取都走宿主服务。拒绝。
- **把刻度轨放进既有「对话操作栏」**：零视觉侵入、入口就地复用。但它丢掉"当前在第几轮"的持续位置感，而位置感正是本能力的核心价值。拒绝（作为常驻轨的替代方案）。
- **持久化"上次读到的轮次"**：对长会话有真实价值，但它是用户标记的变体，会把本次刻意划清的范围弄糊。推迟为独立需求。
- **一期就接大纲（不分期）**：少一次交付。但会让"跨页定位"与"投影契约"两个未验证的东西同时上线；而真正的技术风险在定位机制，它与大纲无关。拒绝。
- **为定位引入第三方可定位列表组件**：省去自己接线。仓库目前没有额外依赖，为单一功能破例不划算，且 `ensureVisible` 已足够。拒绝。

## 与既有决策的关系

- **延伸** ADR 0017：三分能力报告从"宿主服务能力"扩展到"能力 × 该会话数据是否存在"两个维度。
- **遵守** ADR 0006（事件保真契约）：新端点只读、只输出派生的轮次摘要，**不新增会话事件类型**，因此不需要改动事件目录。
- **不改变** 「对话时间线」与「可见事件」的既有定义：轮次导航是叠加在时间线之上的只读定位能力，不是新的时间线展示模式。
- **不改变** ADR 0009／0011 关于移动端 Git 只读导航的任何边界。
- 领域词汇：`CONTEXT.md` 在「对话时间线」小节新增「轮次导航」「刻度轨」「轮次索引」三条。
