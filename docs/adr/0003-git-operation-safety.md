# Git 写操作采用仓库串行的可恢复任务

Status: accepted

Git 写操作由 provider 作为带稳定操作标识的后台任务执行，而不是绑定在一次长 HTTP 请求上；同一仓库的写任务串行，读取可并发，客户端断线后能够恢复进度和最终结果。普通取消只尽力终止运行中的进程，不等同于撤销已发生的变化；merge、rebase 等流程的 abort 是独立 Git 操作，冲突时由用户选择终止流程、交给模型处理或转到电脑继续。

## Consequences

- 启动写操作必须携带幂等键，立即返回操作标识，并通过事件流或查询接口报告阶段、结果和可用后续动作。
- provider 持有仓库级操作协调权，拒绝同仓库并发写入，并能识别来自手机、电脑或其他消费者造成的状态变化。
- 删除、放弃改动、drop stash、reset、clean、force push 等破坏性操作需要服务端签发并校验与仓库、操作、参数和有效期绑定的确认挑战；仅在 App 弹窗不构成授权。
- pull、push 必须显示并绑定明确同步目标；不存在 upstream 时不得猜测 `origin` 或同名分支。
- 客户端只提交仓库标识，provider 负责将其解析到已授权 DSH 工作区，拒绝任意路径、越界路径和失效仓库。
