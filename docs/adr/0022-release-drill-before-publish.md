# 0022 正式发布前必须通过演练

状态：已接受。需求与验收见 GitLab `ahedu/dsh-mobile-remote#37`。

npm 上的版本号**不可回收**（同版本内容不可变、不能覆盖），而"打包 → 发布 → 安装 → 更新"这条链路的失败通常在发布后才暴露：载体别名没落盘、`dist-tag` 打错、安装后插件内容标识与清单对不上、只发了插件没发载体……每一种都只能靠新版本号重来。预检（离线校验）只看本地产物与元数据，看不到真实包管理器的安装与更新行为。

因此决定：**正式发布前必须先跑一次发版演练（drill）并通过**。演练用一个临时本地 registry（演练 registry）承载演练版本的插件与载体，完整走"发布 → 全新安装 → 发现载体 → 版本更新 → 失败路径"，全程不接触公共 npm、不消耗任何公共版本号；演练失败即阻断发布。

取舍与边界：

- 本地演练覆盖不了公共 registry 的可达性、真实体积上限与镜像延迟，因此保留**试发布**（一次性包名或预发布版本，需授权）作为真源验证手段；两者不能互相替代。
- 演练依赖开发者本机的一次性环境（全局安装临时 registry），所以不默认嵌进发布脚本，由 `--drill` 显式触发、失败阻断。
- 演练的判据是外部可观察结果（命令退出码、结构化运行记录、安装后的文件系统事实），不测实现细节。
