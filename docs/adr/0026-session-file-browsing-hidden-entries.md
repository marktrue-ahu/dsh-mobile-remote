# 0026 会话文件浏览按需显示隐藏条目

状态：已接受（2026-11-03）。实现追踪 GitLab issue #45；对应 upstream 分支从同步 `main` 起步，独立 PR。关联：ADR 0014、0016。

## 背景

会话文件浏览复用 `GET /api/directories` 与 `GET /api/files`。前者当前对所有点开头条目统一过滤（`dirs` / `files` / `fileEntries` 都不返回），因此用户无法在手机上查看 `.gitignore`、`.github/`、`.vscode/` 等默认隐藏的配置文件；后者本身没有点文件过滤，路径可读即可预览。

ADR 0014/0016 记录过本能力的信任模型：读取边界在客户端（夹在会话工作目录内），服务端不强制路径授权；已认证用户本身已持有 agent 控制权。它们也记录过「客户端隐藏 `.git/`」的边界。本次需求要求默认隐藏条目可见，需要在不改变既有信任模型、不破坏旧 App/旧 Host 的前提下调整该边界。

## 决策

### 1. 可见范围

- 会话文件浏览在用户开启「显示隐藏文件」后，显示名字以 `.` 开头的**文件和目录**；与普通条目同一列表、正常排序，不分组、不加特殊图标。
- 名称恰为 `.git` 的条目（文件或目录）**始终不显示**，也不进入其内部；worktree 根部的 `.git` 文件同样排除。
- 「隐藏」只按文件名是否以 `.` 开头判定；Windows 隐藏属性不在本次范围。

### 2. 宿主契约：按需返回

- `GET /api/directories` 新增可选参数 `includeHidden=1`；默认行为完全不变（继续隐藏所有点开头条目）。
- `includeHidden=1` 时，`dirs`、`files`、`fileEntries` 使用同一规则返回点开头条目，但永不返回名称恰为 `.git` 的条目。
- 根视图、`POST /api/directories` 新建目录、`GET /api/files` 的文件读取语义不变；隐藏文件的内容预览沿用既有只读文件通道。
- 旧 App 不传参数 → 行为不变；旧 Host 忽略参数 → 新 App 静默降级（看不到隐藏条目，不报错，不新增 capability 位）。

### 3. App 设置与请求

- App 全局 **设置 → 文件浏览 → 显示隐藏文件**，持久化为 app-level 偏好，**默认开启**。
- 仅会话文件浏览器按该开关传 `includeHidden=1`；新建会话/工作区目录选择器保持不传，继续隐藏点开头目录。
- 客户端在进入目录列表时也防御性过滤名称恰为 `.git` 的条目，即使 Host 违约返回。
- 开关在下次进入/下一次目录加载生效；浏览页刷新可用；不做跨页实时监听。

### 4. 记录与交付

- 本 ADR 与 `CONTEXT.md`「隐藏条目」术语只作为 develop 决策记录；上游 PR 不包含 `docs/adr`、`docs/design` 等决策文档。
- 实现放在独立 upstream 分支/PR（`upstream/file-browser-hidden-entries`），不混入其他 Git 浏览 PR；不 bump 版本或发布元数据。
- 文档增量：`docs/03-api.md` 说明 `includeHidden` 参数与 `.git` 排除规则；测试覆盖 Host 默认/开启/`.git`/文件预览与 App 设置/控制器/目录选择器隔离。

## 后果

- 默认开启后，`.env` 等隐藏文件会直接出现在会话文件浏览中，也可被预览；这是“看默认隐藏”的可见性代价。用户可在设置关闭开关；关闭后行为回到旧的“全部隐藏”。
- `.git` 条目不会出现在会话文件浏览列表，也不会作为可点击入口暴露到移动端；显式按路径调用 `/api/directories?path=.../.git` 或 `/api/files` 仍沿用既有只读信任模型，本决策不改变、也不声称阻断该路径。Git 对象库不会出现在手机浏览列表。
- 目录选择器不受影响，避免选择工作目录时被 `.git/` 等干扰；两个入口的可见性语义有意不同。
- 旧 Host 上开关存在但无效果，属于自然降级；不引入版本探测或能力位，避免为一次纯 UI/契约加法扩大兼容面。
- 安全模型不因本决策改变：仍是口令鉴权 + 会话工作目录范围；服务端未新增路径授权强制。隐藏条目可见性属于 UI 边界，不是权限边界。
- Windows 隐藏属性、`.git/` 内部浏览、为目录选择器显示隐藏条目均保持范围外；未来若要支持，需要新的决策。

## 考虑过的方案

- **全局默认显示隐藏条目**：拒绝。会影响目录选择器与所有旧客户端，且没有任何“按用户意愿”的退路。
- **显示 `.git/` 并允许预览内部文件**：拒绝。对象库没有移动端浏览价值，`.git/config` 可能包含远端凭据；收益远低于暴露风险。
- **只显示白名单配置文件（`.gitignore`、`.github/` 等）**：拒绝。白名单不可维护，且会把“隐藏”变成产品猜测；用户明确要的是默认隐藏条目可见。
- **新增 capability 位或独立端点**：拒绝。`includeHidden` 是可忽略的加法参数，旧 Host 静默降级已足够；额外能力位只会扩大契约面。
- **开关默认关闭（用户主动开启）**：拒绝。需求是“能看默认隐藏”，默认开启更直接；关闭开关保留了保守用户的选择。
