# 0032 代理面板独立化（四页签全屏页）

状态：**已接受，待实施**（2026-11-17），设计审定见 GitLab #105 note 2835；实现追踪 #115。关联：ADR 0018（移动端轮次导航）、#101（触发消息显示）、#87（rc.2 subagents 契约兼容）。

> 本 ADR 记录**设计与范围决策**。#115 尚未开工，实施细节以该 issue 的规格为准。

## 背景

#105 最初把「Agent Teams」当作子代理列表的一个**附加视图**：在既有「会话工具」弹层（任务 / 子代理 / 目标 三页签）里，给子代理页签加一层 Team 组织。

设计稿评审时维护者指出该定位不足：

> 我看了 issue 105 的设计图，决策里要求 team 和子代理一个面板，设计图里没有体现。我建议子代理独立出来和 team 合并在一个面板里，因为后续还要有任务面板、消息、团队成员，并且只在主会话中能打开，子代理会话不能打开。

关键信息在「后续还要有」：任务板、消息、团队成员。这四项都属于**主会话对下属代理的治理**，而不是「会话工具」（任务 / 目标）的一部分。塞进三页签弹层会在内容增长时撑爆。

同时暴露出三个实现层问题，都在设计阶段实测发现：

1. **`TabBar` 压缩标签宽度时不报 overflow**。M3 把 80pt 的格宽扣成 68pt，而「子代理」文字需 81pt，**字被裁掉但溢出回归全绿**。
2. **服务端未下发代理名**。`lib/index.js:11032` 只输出 `title`（`label ?? rowName ?? rowTitle ?? …`），`rowName` 在 `:11006` 已被当作 title 的 fallback 用掉。
3. **gating 单点不足**。只在渲染层隐藏入口时，若持久化顺序里残留 `agents` 动作，子代理会话仍可能把面板打开。

## 决策

### 1. 新建独立「代理」面板，四页签

- 标题「代理」，**全屏页**（`Navigator.push` + `MaterialPageRoute`），与 Git 管理页同构
- 四页签：**子代理 / 团队 / 任务板 / 消息**
- 本次实现前两块；后两块用**说明性空态**占位（文案「将在后续版本并入本面板」），不灰显、不隐藏——先固定结构
- 子代理从「会话工具」弹层移出；会话工具只留「任务」「目标」

### 2. 仅主会话可打开，且两处都要拦

- `Session.isSubagent`（`origin == 'subagent'`，ADR 0013）为真时，**入口整项不渲染**（不灰显——灰显会招来反复点击与「为什么不能开」的疑问）
- `_openConversationActionRail` 的 action 分发层**再校验一次**；只做渲染层过滤不够

### 3. 页签等分，不用可滚动居中

- `格宽 = (宽 − 8) / 4`，**不预先扣除 `labelPadding`**
- `letterSpacing` 固定为 0（主题自带 0.3，三个汉字多 0.9pt）
- **测量与渲染必须同源**：TextPainter 不带主题 tracking 时，「量出来放得下」与「渲出来被裁」会不一致
- 字号按**实测反查**：线性估算给出 98.8% 却实际溢出（字形 advance 有取整）
- 320pt × 2.0× 下取 **96.3% 字号**（13.5→13.0）；≥2.3× 退化为滚动——这是唯一放弃等分的地方

### 4. 子代理行显示模型信息（模型 + effort）

- 竖排三行：会话标题 13.5/ink → 代理名 · 时间 11.5/ink3 → **模型 · effort** 10.5/ink2
- **模型行横跨整行**，不放进标题列——放列里时与「中断」抢宽度，320pt×2.0× 那列只剩 140pt，而模型名要 163.6pt
- **不显示 provider**（维护者明确要求）
- 两级截断：`模型 · effort`（默认）→ `仅模型`（超长模型名时）
- **effort 需映射**：`/session-config` 返回 id（`"high"`），从 catalog 的 `efforts[].id → name` 查表得本地化名（「高」）
- 懒加载：行进入视口才发请求，并发上限 3

### 5. 服务端补两个字段

- `/subagents` 每行补 `name: row.rowName`（**实现阻塞**：不补则「副行 = 代理名」拿不到数据）
- `/sessions` 每项补 `parentSessionId`（按父聚合子节点、判断是否根会话都需要）
- 树结构：去掉 `.filter((row) => row?.depth === 1)`，透出 `depth`；rc.1 或降级路径无 `depth` 时标 `multiLevelUnavailable: true`

## 后果

### 收益

- 面板有明确的**归属语义**：它管的是「这个主会话派生了什么、它们在干什么」，与会话自身的工具（任务 / 目标）分开；
- 四块结构一次定死，后续加「任务板」「消息」不需要再改导航；
- 全屏页比底部弹层多出可用高度，且与 Git 管理页进出语义一致（都是「进入一个子页面」而非「拉起一个临时的浮层」）；
- gating 明确「子代理不治理子代理」，与 CONTEXT.md 既有的领域规则（子代理不向用户提问）同源。

### 代价与约束

- **`TabBar` 的溢出回归不可信**。压缩标签宽度时不报 overflow，必须用「实际渲染宽度 > 格宽」判定，并保证测量与渲染同源。
- **`AppBar` 有同类问题**：两行标题在默认 56pt toolbar 下，2.0× 纵向压掉 13pt、3.0× 压掉 47pt，同样不报 overflow。`toolbarHeight` 必须按字号计算。
- **`/session-config` 是逐会话接口**，N 个子代理要 N 次调用。懒加载 + 并发上限 3 是当前的折中；若将来子代理数量增长，应把 model/provider/effort 合并进 catalog 响应，而非提高并发。
- **降级提示条必须是页签级而非面板级**：团队任务板不依赖多层能力，不应被「仅显示直接子代理」污染。
- 代理面板不提供团队的创建/编辑；团队开关（`team/mode`）放在模型/effort 菜单，面板内只显示只读状态 + 「前往设置」。

### 不受影响

- 「会话工具」弹层保留，仍管任务与目标；
- 子代理的层级展示沿用 #105 已定的视觉结论（默认折叠、自绘三角、树形导轨 `ink2@78%`、缩进 14pt / 最多 3 级、降级不渲染胶囊）；
- Agent Teams 的完整交互（开关写路径、成员管理）留给 105b；
- 轮次导航、分批、长结果裁剪等既有契约不变。

## 未采纳的替代方案

**在「会话工具」三页签里加 Team 页签**：改动最小，但四个内容块会把页签撑到 5+ 个，且「子代理/团队」与「任务/目标」语义分属两层（治理 vs 会话自身），混在一起后难以解释。

**底部弹层（`showModalBottomSheet`）**：第一版设计稿采用此方案。全屏页相对它的实际收益是**可用高度**与**进出语义一致性**，而不只是美观。

**`isScrollable + TabAlignment.center`**：第一版采用，实测页签按内容宽度紧排，「挤在一起」。改为等分后又遇到裁字问题，最终用「等分外 + 实测反查字号」解决。

**在面板内直接放团队开关**：网页端停用团队需要二次确认（`TeamDisableConfirmation`），手机上多一处写路径就多一套确认与失败回滚。选择只读 + 跳转。

## 验证（设计阶段）

- 三组必测条件全部通过：**320×2.0×**（13.00 字号，96.3%）、320×1.5×（13.50，100%）、390×1.5×（13.50，100%），均无裁字；
- 溢出矩阵 16 组（浅/深 × 1.0/1.3/1.5/2.0 × 两页签）0 失败；
- 对比度逐项实算，两处 FAIL 已定位：副行 `ink3` 2.54:1 是**全 App 既有问题**（建议单独开 issue，不在本 issue 只改面板）；`warn` 3.28:1 只够图形不够文字，故「依赖阻塞」用 `ink2`、`warn` 只给禁止符；
- 回归断言 `verify_v2_test.dart` 6 条全部通过。

## 未验证项

- 懒加载的延迟预算（设计阶段未连真实宿主，时间线为设计预算）；
- 浅色主题仅做 320×2.0× 交叉验证；
- 真实安全区高度；
- 超长代理名（>14 字符）在 320×2.0× 下会省略（差 34pt），建议维持并在详情补全名。
