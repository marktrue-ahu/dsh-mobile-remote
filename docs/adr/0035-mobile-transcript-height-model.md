# 0035 手机端对话页高度模型：顶对齐、固定行高与展开上限

状态：已接受（2026-11-19），**已实施（2026-11-19），待真机验收**。实现追踪 GitLab #126/#103/#114；本 ADR 只约束展示层高度模型。完整 DSH Chat 语义（command/compaction/retry/developer/context/unknown、node/group 树、reasoning block 边界、每轮 usage 等）是远期目标，见 GitLab #127，不在本 ADR。关联：ADR 0018（gutter/轮次导航）、ADR 0027（轮次过程）、ADR 0028（过程区视觉）、ADR 0029（四档 v4）、ADR 0031（滚动 owner）。

## 背景

#126 真机出现“分批隐藏 + 底部大段空白”；#103/#114 长期围绕“运行中脱底、上翻困难、空白”反复修复。根因不是某一个滚动函数，而是展示层没有稳定的高度模型：

- `_liveBottomGap` 用估算的 `scrollExtent` 判断“内容是否短于一屏”，而 gap 自己又进入 `maxScrollExtent`，形成 **gap↑ → max↑ → 判定不短 → gap↓ → max↓ → 判定短 → gap↑** 的反馈环；
- 50 行分批让“实际很高但未渲染”的内容被误判为短内容，进一步放大这个环；
- 过程组/工具卡/思考详情的无界内联展开，会让同一个列表条目在**没有新事件**时大幅改变高度，滚动 owner 只能不断校正。

DSH 本体的做法是：折叠态单行；展开态固定上限（过程组 body `min(400px, 50vh)`、工具详情 320/260/150、命令 260、上下文 141），超出内部滚动；四档只控制结构可见性，单个工具/思考详情始终手动展开。手机端此前没有这套上限，且“完全展开”会自动展开当前轮详情（ADR 0029），进一步放大了自动高度变化。

本 ADR 的目标是把 live 视图的高度变化压到少数、可预测、可测量的情形，而不是继续给滚动函数叠补丁。

## 决策

### 1. 短内容顶对齐，删除底部占位

- live 视图内容短于视口时**顶对齐，下方留白**；不再把内容推到底部。
- 删除 `_liveBottomGap` 及其测量/判定全套：`_scheduleLiveBottomGapMeasure`、`_lastGapContentExtent`、`_lastGapViewportHeight`、`contentExtent`/`shortEnough`/`desired`、`_livePlanHasHiddenRows`、`debugLiveBottomGap`。
- 这取代 issue #77 的“短内容贴底”决策。#118 的“空白”重新定义为：**短内容下方留白是预期**；只有内容被推离顶部、上方出现不可滚动空白、或滚动位置越界才是 bug。
- 保留 `_clampOverscrollAfterShrink`（内容变短后的范围夹回）与 `ScrollFollowCoordinator` 的意图/校正语义。短内容首次打开时意图仍是 `followLatest`；内容一旦超过一屏，由 owner 校正到底部，不因顶对齐把用户误判为阅读态。
- 本决策只约束 live 视图；历史分段视图（`_inHistory`）保持现状。

### 2. 折叠行固定单行，展开正文固定上限

- 过程行/工具行/思考行折叠态固定单行：`24dp × textScaler`，超长省略，状态 chip 不换行。
  例外：工具折叠行带图片 chip 时保留 `32dp` 独立命中区（#74），其余仍按 24dp。
- 过程组 body：`min(400dp, 50% 窗口高度)`。
- 其余可展开正文（工具参数/结果、思考正文、用户消息）：`320dp`。
- 助手最终回复**不设上限**（主内容必须完整内联）；超长摘要仍走“查看全文”按需加载详情。
- 用户消息超过 320dp 时在框内滚动；摘要被服务端截断时提供“查看全文”，按需加载详情后仍在 320dp 框内滚动。
- 图片：每张高度取 `min(320dp, 网格上限)`，按 metadata 的 width/height 定比例；图片网格整体 `min(400dp, 50% 窗口高度)`，超出点“查看全部”进图库，**不做网格内层纵向滚动**。
- 上限取**窗口高度**而不是滚动视口高度，避免键盘开合改变 cap 造成额外 resize；旋转/分屏允许重算。
- 思考展开也设 320dp。DSH 的 reasoning 展开本身没有独立 `max-height`（它在组体内时受组体上限约束）；手机端统一 cap 是有意适配，不宣称与 DSH 逐像素一致。

### 3. 内层滚动：C 方案

- 只有内容溢出上限时，展开正文才启用内层纵向滚动；内容未溢出时不得拦截父列表手势。
- **不做边缘滚动交接**：内层滚到顶/底后，继续拖动不会带动外层列表；用户从标题/行/列表其他区域起手滚动父列表。
- 内层滚动必须保留 ADR 0031 §6 的 `depth != 0` 过滤：内层 `ScrollEnd`/metrics 不得改写主列表意图。
- 内层滚动最多两层（过程组 body + 详情 body）。实现前必须做手势 spike；若两层嵌套导致上翻困难，优先保留组体滚动，详情体改用“查看全文”sheet，而不是继续叠手势。
- 加 scrollbar/渐隐提示。真机若“上翻困难”明显，再评估边缘交接（A）或退回“裁剪 + 查看全文 sheet”（B）；本轮不先做 A。

### 4. 四档保留；详情手动；删除活动条

- 四档（简洁/标准/详细/完全展开）和两档收起时机保持不变；档位只控制过程段/组/行的可见性。
- **完全展开不再自动展开当前轮详情**：思考正文与工具卡详情在所有档位都手动展开。理由：即使单个 body 有 320dp 上限，N 个工具一次自动展开仍是 N×320 的自动高度变化；DSH Verbose 的单个详情也是手动。
- **删除活动条**（`_ActivityBar`/`_buildActivityBar`/活动条几何刷新）。它同时展示思考与工具状态，与过程行/组抬头/顶部状态点重复，且显隐改变消息视口高度。
  - 工具运行状态由过程行承载；组抬头只保留既有的计数/“进行中”汇总，不再由独立活动条重复当前工具名；
  - 思考状态：简洁用过程段摘要（“思考中…”）、标准用组抬头、详细/展开用 provisional 思考行；
  - 运行中尚无持久过程行（没有过程段/组可承载）时，用一行 provisional-only 状态：简洁/标准一行“思考中…”文本，详细/展开显示 provisional 思考行；不重建活动条；
  - 顶部 `_StatusDot` 继续只表达连接/会话运行状态，不承载命令/思考文本。
- gutter 恒定 `38dp`，回底按钮/刻度轨 overlay，不再 16/36/38 切换；正文宽度不再随控件显隐 reflow。

### 5. 取消 50 行分批

- 删除 `batchProcessRows` 的截断、`processBatchSize`、`_processRowLimits`、`ProcessBatchWindow`、“显示更多”入口及 `_livePlanHasHiddenRows`。
- 保留 `SliverList` 懒构建；过程行不再因行数被内容裁剪。行数很多时由组体上限/内层滚动控制可见高度。
- 这一条取代 ADR 0027 §2 与 ADR 0029 §3/§6 的“50 行分批仍生效”。

### 6. 本轮不做的事

- 不换 `center` 列表结构，不做 reverse / 底部锚定列表重写。
- 不做过程行的 sliver 扁平化或内层懒列表；先按“构建全部行 + 上限内滚动”实现并实测 #103 长会话，超预算另立 issue。
- 不修完整 DSH Chat 语义（见 #127）。
- 配套的“可见内容对齐”（SSE 丢字段、用户长消息详情、仅图片 assistant、思考完整字符串）是 bug fix，不改变本 ADR 的高度模型；它不授权扩展未知事件载荷。

## 后果

- #77 “短内容贴底”正式退役；依赖 `debugLiveBottomGap` 的测试需要改写/删除，`batch_hidden_bottom_gap_test` 不再成立。
- #118 的验收从“内容底部贴设计底边”改为“内容顶部贴设计顶边；短内容下方留白是预期”。
- 活动条相关测试与 `_activeTools` 的显隐逻辑需要收敛；标准档组抬头/简洁档段摘要要补“思考中/进行中”文案，否则删活动条会丢运行反馈。
- 内层滚动有明确的 UX 代价（无边缘交接）；真机若上翻困难，按第 3 节回退。
- 固定上限让自动高度变化有界，但流式正文、最终回复、手动展开仍会改变高度；`ScrollFollowCoordinator` 仍是唯一 owner，不能因为“高度稳定”就信任懒列表估算值。
- 四档的“完全展开”信息密度会低于 ADR 0029 的原语义（不再自动详情）；这是主动取舍，待实机验证是否可接受。


## 实施记录（2026-11-19）

- 布局：删除 `_liveBottomGap` 及测量/判定全套、50 行分批与“显示更多”、活动条及其几何刷新；新增 `_CappedScrollBody`（固定上限、内容溢出才滚动、不做边缘交接）。
- 数据对齐：SSE 转发补齐 `callSummary`/`resultSummary`/`detailTextChars`；`/event-detail` 为 `user/message` 补 canonical `text`、为 `assistant/message` 补完整 `reasoning`；仅有图片的 assistant 不再整条跳过；长用户消息/思考在“查看全文/首次展开”时按需加载。
- 四档：完全展开不再自动展开详情；工具状态只由过程行/组抬头承载；思考状态按 §4 落到摘要/组抬头/provisional 行。
- 过程块宿主：live 轮的过程块优先锚定在 `_items`（center 之后），不跟随早期事件跑到 `_olderItems`；否则补页后 live 侧只剩零高度行，center 边界会出现大块空白（#126 真机 `min=-1673/max=0/extent=44`）。
- 测试：因行为退役，删除 `batch_hidden_bottom_gap_test`、`issue84_visible_tool_dedupe_test`、`issue77_live_scroll_test`、`issue89_scroll_overscroll_test`、`issue118_detailed_mode_blank_test`、`issue118_subagent_follow_blank_test`；新增 `issue126_visible_content_parity_test`。当前 `flutter test` 1723 通过 / 1 skip，`flutter analyze` 0 error/warning，`timeline-contract-check` 181 PASS，`account-usage-check` 15 PASS，Kotlin `UsagePanelModelTest` PASS。
- 门禁遗留：`node --test test/*.mjs` 在 `release-pairing` 的“APK 内部版本实读”上失败（`aapt`/`aapt2` exit 1）；已在干净 HEAD 同环境复跑并得到同样失败，属**基线环境红灯**，与本 ADR 改动无关。交付时按 AGENT-RULES 的基线例外流程登记。
- 真机实测（2026-11-20，会话 256144d7，134→192 项）：live 底部已收敛到 `max=566.7 extent=1218 blank=6.0`，大空白消失；但历史侧 `SliverList` 在只构建 1 个子项时会把 `max` 估到 38090、`extent` 估到 38742，随后才修正。说明“过程块仍是单个 Column 子项”会让懒估算放大；后续需把过程块/组拆成 sliver 子项（本轮未做）。
- 未验证：真机 320/390、浅/深、1.0/1.5 字号；#103 长会话性能；内层滚动边缘 UX。交付前必须真机复验，不能以 widget 测试代替。

## 被否方案

- **保留底部占位 + 单向状态机**：仍要为“短内容”测量并处理反馈；用户明确短内容顶对齐，删除更简单。
- **reverse / 底部锚定列表**：能天然解决短内容对齐，但会重写历史 prepend、轮次定位、#114 几何测试；ADR 0031 也明确不在无证据时换结构。
- **逐类型复刻 DSH 上限（320/260/150/224/360/141）**：更贴 DSH，但组件/测试复杂度高；本轮用两档（组体 + 320）足够。
- **所有正文统一 320（含组体）**：组体多行时过矮，且与 DSH 组体 400/50vh 差距大。
- **详情全部出层（sheet/page）**：几何最简单，但偏离 DSH 内联语义；本轮保留内联 + 上限。
- **保留活动条但固定预留/overlay**：用户明确“展示地方太多”，且工具状态已在过程行；删除。
- **完全展开继续自动详情**：即使有 cap，N 个工具仍造成大块自动高度变化；与 DSH Verbose 也不一致。
- **本轮就做过程行懒构建**：结构改动大、回归面广；先实测，必要时另立 issue。

## 修订的既有 ADR

- ADR 0027 §2：删除“展开后单轮过程行超过 50 条分批展示”，由本 ADR §5 取代；四档策略表由 ADR 0029/0035 修订。
- ADR 0028 §4：删除“50 行分批”“单卡默认收起/详情自动展开”的冲突表述；单卡详情的上限/手动语义按本 ADR §2/§4。
- ADR 0029 §2/§3/§5/§6：删除“完全展开当前轮自动展开详情”“50 行分批仍生效”“活动条”行；四档结构语义保留，详情一律手动。
- ADR 0031 §6：内层滚动允许存在，但必须保留 `depth != 0` 过滤；本 ADR §3 明确不做边缘交接，短内容顶对齐取代旧的底部占位行为。
- ADR 0018 的 gutter 16/36/38 切换：由本 ADR §4 的恒定 38dp 取代；轮次导航定位语义不变。

## 验证（实施后）

- widget：短内容顶对齐且无 gap；固定行高/上限；内层滚动只在溢出时启用；无自动详情；活动条删除后四档仍有思考/工具状态；gutter 恒定 38 不 reflow。（已由 1723 例全绿覆盖主要路径）
- #126：取消分批后无“显示更多”、无大段空白；长会话可上翻。
- #103：工具卡展开/收起不脱底；长会话可连续跟随。
- #114：四档 × 跟随/阅读的关键轨迹；同一 ChatScreen 内完成“运行→完成→收起”；校正有界、无自激。
- 真机：**未做**。320/390、浅/深、1.0/1.5 字号；长会话性能记录；内层滚动边缘 UX 明确记录为已知限制。
- 未验证项必须如实保留：内层滚动边缘体验、长会话构建耗时、真机 Android 滚动物理。
