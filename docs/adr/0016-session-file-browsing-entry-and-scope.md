# 0016 会话文件浏览：入口在对话操作栏，浏览根是会话工作目录

状态：已接受。**取代 [0014](0014-workspace-file-browsing.md)**（该决策把入口放在应用级抽屉、作用域定为全局选中的已注册工作区，需求对齐后确认是错的）。

手机端「文件浏览」的入口在**对话操作栏**（聊天界面右上角「对话操作」⋮ 展开的窄栏），与 Git 导航并列；浏览根是**当前会话的工作目录**。背景与验收见 GitLab `ahedu/dsh-mobile-remote#15`。

## 为什么改

上一版已发布（v3.1.5+37）并在真机上验证，暴露两点：

1. **入口位置错了**。原始需求里的「侧边栏」被理解成主页抽屉，实际指的是对话操作栏。这两者在产品里是不同层级的东西：主页抽屉是**应用级**导航（首页/会话/设置），对话操作栏是**会话级**动作集合。放在抽屉里意味着"浏览文件"被表达成一个跨会话的全局能力，与用户心智不符。
2. **作用域随之错了**。既然入口在会话里，浏览的就该是"这个会话的项目"，而不是"我在首页筛选选中的那个工作区"。原设计还让浏览页写回全局 `workspacePath`，进一步把两个层级的状态搅在一起。

## 决策

**浏览根 = 会话工作目录**（`Session.cwd`），与同一操作栏里的 Git 导航同源。取不到就不浏览——给出原因与重试，**不回退**全局选中工作区，也不提供页内工作区切换。理由：回退会让"看这个会话的文件"和"看别的目录"在同一页面里语义分叉，而这正是 Git 侧 `authorizedRoot` 已经拒绝的事（会话 cwd 必须落在已注册工作区内，否则 403）。宁可明确说"这个会话没有工作目录"，也不给一个看起来能用、实际指向别处的页面。

**不读写全局 `workspacePath`**。那是首页会话列表的筛选状态，属于应用级；会话级能力碰它会造成"打开文件页顺手改了首页筛选"的隐性耦合。

**信任模型不变**：仍复用 `GET /m/api/directories` 与 `GET /m/api/files`，不新增会话授权接缝（该取舍与代价见 0014，仍然成立）。客户端"夹在浏览根内"是防误操作，不是安全边界；服务端不强制，越权路径由 `#16` 独立跟踪。

## Consequences

- 新增动作会改变操作栏的动作集合：`conversationActionIds` 从 3 项变 4 项后，旧设备上持久化的顺序因长度不等被判无效并回退新默认。这是**有意的**——用户只丢一次自定义排序，胜过恢复出一个缺项/未知项的顺序。已加测试钉住。
- 「文件」排在 Git 之后：两者都是「当前会话的项目」的观察入口，相邻才符合用户找东西的顺序。
- 无工作目录的会话（部分休眠/归档会话）看不到文件；这是接受的代价，也是与 Git 导航一致的行为。
- 浏览页不再需要工作区选择/切换的 UI 与状态，控制器从"工作区级"简化为"会话级"：根一旦确定就不再变化。
- 与 0014 相同的其余代价继续有效：`/directories` 成功响应回显服务端绝对路径（与 Git 侧"响应不含主机路径"相反）；纯只读，不复用 `POST /m/api/directories`。

## 一个真机 bug 的教训（不改变决策，但值得记录）

上一版控制器写的是 `api ?? Api()`，而 `Api.baseUrl` 默认为空串、要由启动流程从 SharedPreferences 载入。于是它绕开了已配置的全局单例，拼出 `/m/api/...` 这种没有 scheme/host 的 URL，真机上表现为「无法读取目录：No host specified in URI」。

这条与本次需求变更无关，但**同一行代码在 0014 的实现里就已存在**——当时没有在真机上打开过入口，所以没暴露。现在默认复用全局 `api` 单例（与 `chat_screen` 的 `_api` 同一约定），并在 `session_files_api_regression_test.dart` 里用**真实 HttpServer** 钉住：默认构造的控制器必须把请求发到已配置的 host 上。该测试已用"把实现改回 `Api()`"验证过会变红。

## Considered Options

- **保留抽屉入口，再加一个操作栏入口**：两处入口两套作用域，用户会问"为什么两个文件入口看到的目录不一样"。拒绝。
- **操作栏入口 + 回退全局工作区**：无 cwd 的会话也能用，但同一页面有时看会话项目、有时看全局筛选，语义不稳定。拒绝。
- **改由服务端为文件浏览分配会话授权身份**（与 Git 完全对齐）：能收紧边界，但那是 `#16` 的安全决策，且会让"浏览不含 Git 仓库的目录"这一目标落空。拒绝附带完成。
