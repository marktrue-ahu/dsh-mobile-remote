# 0006 Markdown 围栏解析：手写实现，不引入第三方包

日期：2026-09-21
状态：已接受

## 背景

手机端 Conversation timeline 的 Markdown 渲染为手写实现（块级解析 + 自定义渲染组件：代码卡片、表格、行内规则、链接白名单）。issue #9 报告：4 反引号文档围栏包裹 3 反引号代码块时渲染错位——围栏判定是「以三反引号开头」的二元翻转、不记录开启长度，内层开启行被误当作闭合行，导致同一段内容被拆成「半代码卡片 + 半正文」。

## 决策

1. **围栏解析按「开启反引号数量 N」配对**：闭合行须仅由 ≥N 个反引号组成（允许尾随空白）；开启行信息串含反引号则不算围栏；开启行缩进有意不做限制（保住列表内缩进的代码块）。
2. **保持手写实现，不引入第三方 Markdown 包**（候选：`markdown`、`flutter_markdown_plus`、`gpt_markdown`）。

## 理由

- `flutter_markdown` 已于 2025-04-30 停止维护；
- Dart 官方 `markdown` 为纯解析包，接入需重写现有自定义渲染层（代码卡片、表格、行内规则、链接白名单），回归面大于缺陷本身；
- `gpt_markdown` 面向 AI 输出，但会引入 `flutter_math_fork`、`highlight` 等额外依赖与体积；
- 本次缺陷根因单一（围栏配对），最小补丁即可修复，且不新增依赖。

## 后果

- 围栏语义遵循 CommonMark：4 反引号围栏内的**全部内容**（含内层代码行与 Markdown 正文行）统一渲染为**一个**代码卡片——修复前「半卡半正文」的错位消失。
- 其它 CommonMark 缺口（标题仅 1–4 级、嵌套列表/引用、任务列表、删除线、行内 HTML、图片）仍不支持；需要时另立决策。
- 若未来引入 Markdown 包，须以本 ADR 记录的自定义渲染能力（代码卡片行数与复制、表格样式、行内规则、链接 scheme 白名单）作为迁移验收基线。
