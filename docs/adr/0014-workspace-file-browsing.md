# 0014 工作区文件浏览复用任意路径目录通道，不引入会话授权身份

状态：**已被 [0016](0016-session-file-browsing-entry-and-scope.md) 取代**

> 取代说明：本决策关于「复用既有目录/文件通道、不引入会话授权身份」的取舍**仍然成立**，
> 0016 继续沿用。但其中「入口放在应用级抽屉」「作用域是全局选中的已注册工作区」
> 两点在真机验证后确认与需求不符，已由 0016 改为「入口在对话操作栏、浏览根是
> 当前会话工作目录」。阅读时以 0016 为准。

手机端新增对**已注册工作区**的只读文件浏览（目录结构 + 文件内容预览），入口放在应用级侧边栏（抽屉），作用域是当前选中的已注册工作区而非聊天会话。背景与验收见 GitLab `ahedu/dsh-mobile-remote#15`。

本决策的关键取舍：该能力直接复用既有的目录列举与文件内容通道（`GET /m/api/directories`、`GET /m/api/files`），而不是像移动端 Git 那样走「会话解析授权目录 + 服务端分配身份 + DTO 不含主机路径」。理由是这两条通道本就以「口令鉴权 + 手机端显式指定路径」为信任模型，其任意路径浏览是**有意保留**的能力（新建会话需要跨盘选择工作目录）；在其上叠加会话授权身份会形成第二套互相矛盾的路径模型，且无法覆盖「浏览一个不含 Git 仓库的目录」这一目标——而 `已注册工作区` 本就允许不含 Git 仓库。

明确接受并记录的代价：

- 该能力的读取边界在客户端（夹在工作区根内、隐藏 `.git/`），**服务端不强制**；越权的手机端仍可直接调用既有通道读取任意可读路径。这与既有的目录选择器同等级——已认证用户本就持有 agent 控制权。
- `GET /m/api/directories` 的成功响应会回显服务端绝对路径，与 Git 侧「响应不含主机路径」的约定相反。本能力接受该差异。
- 本能力是纯只读：不复用 `POST /m/api/directories`（新建文件夹）。

## Consequences

- 浏览页面不依赖 Git 能力可用性，也不依赖 `gitReadProvider`；Git 不可用时它仍然工作。
- 文件内容预览的渲染层自建为不依赖 Git 模型的通用只读文本组件，为将来 Git 预览复用它留出空间；本次不改动 `git_browser_sheet` 的既有预览。
- 入口沿用「能力不可用时仍可见并说明原因」的既有范式；因为作用域是工作区级，在未注册任何工作区或未选中工作区时由页面给出原因与重试，而不是隐藏入口。
- 既有 `/m/api/files` 缺少工作区包含校验与句柄级保护的问题由 `#16` 独立跟踪；本决策不因此改变对该通道的使用方式，但也不声称它已被加固。

## Considered Options

- **新建会话/工作区授权接缝**（与 Git 一致）：授权面最小，但要新增服务定义、provider、能力协商与移动 DTO 等多处登记，且无法覆盖非 Git 目录；成本远超本次价值。
- **先收紧既有通道再复用**：更安全，但会让目录选择器的跨盘选目录能力失效，属于独立的安全决策，不应由本功能附带完成——已拆为 `#16`。
- **允许向上走出工作区根**：等于把移动端变成完整文件系统浏览器，放弃本能力唯一的客户端边界，拒绝。
