# 插件只支持当前 DSH 代际，并以能力探测而非版本判断判定兼容

Status: accepted

插件把受支持宿主收敛为上游当前已发布的 Typert 代际（依赖范围写作 `^0.1.5-rc.2`），不再为更早代际提供适配保证。旧代 Remote 调用通道的提供者 `@deepseek-ai/dsh-host-apiproxy` 上游最高只发布到 `0.1.1-rc.2`，在新代宿主中根本不存在，因此保留其消费代码只会积累不可达分支。仍然为旧代宿主保留的交互通道保持可用，但输出显式弃用日志提示升级内核。

兼容性判定改用能力探测而非版本号。插件分别探测 Remote 调用入口、Remote 事件桥入口、冷会话恢复入口三项独立能力，缺失项使对应功能以明确错误失败，并在环境诊断中如实上报。宿主版本号只用于诊断展示与升级提示，不参与任何功能门控，插件也不拒绝加载在范围外的宿主。

选择能力探测而非版本判断，是因为两个真实故障都落在「版本一致但能力不同」的边界上。旧一代宿主提供了 Remote 网关服务与调用方法，却没有事件流面，因此以「调用方法是否存在」为判据会得到「声称新代、事件桥未启动」的不一致结论——功能静默失效而诊断宣称正常。另一方面，profile 的依赖副本只增不删，可能比宿主更旧或留下断链，使版本字符串不足以承载功能开关。

放弃旧代适配的代价是：问询与审批的结算依赖上游未承诺的 `$events/result` 通路，一旦上游变更该通路，问询与审批将彻底失效而不是降级；插件无法再通过换用旧代交互通道来兜底。该风险由诊断中的能力上报承担——使用者能看见能力缺失，而不是面对一个静默失效的功能。

## Consequences

- 依赖声明收缩为当前代际范围，安装期即可发现明显不匹配，不必等到运行期。
- 新增或替换内核服务时，判定依据落在能力探测上，因此同代补丁发行版不需要重新核对版本清单。
- 诊断必须同时给出宿主版本号与三项能力结果：版本号用于身份识别，能力结果用于行为判断，两者不可互相替代。
- 未文档化的交互结算通路成为单点依赖，其失效不再有降级出口，只能明确报错。
- 旧代宿主的使用者仍可使用主要功能，但会在日志与诊断中看到明确的升级提示；旧代问询/审批帧桥的静默行为不再是唯一的失败表现。
