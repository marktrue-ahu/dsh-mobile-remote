# 移动端 Git 收敛为只读导航

Status: accepted

移动 App 的 Git 能力收敛为“移动端 Git 只读导航”，只提供当前聊天会话授权仓库的分支列表、最多三个引用的分支图和提交详情。App 不再提供状态、工作区 diff、暂存、提交、分支修改、远端同步、冲突处理或任何其他 Git 写入口，也不为 AI 操作提供专用按钮。用户需要修改仓库时，直接在现有聊天中向 AI 表达意图，实际执行完全沿用 Agent 的 sandbox、权限审批和工作区边界，不属于移动 Git 契约。

该决策取代 ADR 0001 的“日常 Git 闭环”和 ADR 0003 的“可恢复 Git 写任务”。ADR 0002 的 Service Definition / Provider / Consumer 接缝继续有效；ADR 0005 的 tip 绑定短期图快照继续有效；默认 provider 分发由 ADR 0004 规定。

## Consequences

- 聊天页右上角在“任务、子代理、目标”左侧固定显示 Git 导航入口。入口打开可拖动、默认接近全屏的底部抽屉，默认显示分支列表；provider 或仓库不可用时入口仍可见并说明原因。
- 分支列表只展示本地/远程身份、当前标记、tracking 和 ahead/behind，支持名称本地过滤；点击分支进入只选择该引用的分支图，不产生分支操作。
- 分支图选择集包含一至三个引用，选择仅在当前抽屉生命周期保留；纵向到底自动按同一 snapshot 分页。仓库变化时保留当前列表和图并提示刷新，不自动重排；引用失效后要求重新选择，不静默回退。
- detached HEAD、unborn branch 或没有本地分支时使用确定性只读回退：指向 HEAD 的本地引用、首个本地引用、首个远程引用；没有引用的仓库显示明确空状态。
- 提交详情显示作者名、时间、OID、完整消息、父提交、引用与 tag、变更统计和可分页文件列表；默认不暴露作者邮箱，也不提供完整 patch。
- Git Service Definition 和移动 API 不包含写意图、operation、challenge、cancel、handoff 或恢复状态。旧写路由在 develop 清理任务中直接删除，不保留执行兼容层。
- 只读替代实现合入 develop 后，独立清理旧 B0–B3、Flutter 写 UI、写 API、执行器和测试。升级时先停止旧执行器，再删除全部旧 Git operation/challenge 持久状态，包括非终态与 unknown-result；该迁移是明确接受的不可逆清理。
- 既有 Git 写行为若仍有需求，应由普通 AI 会话或桌面 Git 工具承担，不得重新包装为移动 Git 写 API，除非未来通过新的领域决策重新打开范围。

## Considered Options

- 保留完整移动 Git 日常闭环：功能强，但移动 UI、后台任务、安全协议和兼容成本远超高频使用价值。
- 只隐藏写 UI、保留执行后端：短期兼容，但继续承担攻击面和维护成本。
- 只读导航、写操作交给普通 AI 会话：聚焦手机高频浏览，复用既有 Agent 安全边界；当前采用。
