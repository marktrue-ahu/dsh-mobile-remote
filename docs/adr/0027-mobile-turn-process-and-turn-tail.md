# 0027 手机端会话内容对齐桌面：轮次过程折叠与轮末产出物

状态：已接受（2026-11-06），**2026-11-11 alpha.12 真机验收通过**。实现追踪 GitLab issue #52（M1 轮次过程与展示模式）、#53（M2 轮末产出物与文件预览）、#54（M3 Batch 1）、#66/#67/#68/#69/#70/#71（M3 Batch 2 与视图收尾）、#73–#79（验收回归修复），均已实施。关联：ADR 0006、0010、0016、0017，以及 issue #1 的需求变更记录（本 ADR 修订其边界）。

## 背景

桌面端 Web 客户端的「看起来像在做什么」主要有两层：一是每轮把思考与工具调用组织成过程组／整轮，可按时机折叠（展示模式四档 + 收起时机）；二是轮次末尾呈现改动文件卡与交付文件卡（以及收尾正文里的行内文件链接）。手机端当前只有单卡折叠：每条工具调用一张通用卡平铺在时间线里，思维链聚合成一个块钉在正文上方，轮末没有任何产出物卡片。

issue #1 当年决定「assistant/tool 产出文件的元数据不再下发，时间线不提供下载入口」。那条决定针对的是把文件元数据挂在消息/工具条目上、鼓励逐条下载；本轮需求是**轮末产出物的只读预览**，语义不同，需要显式接续而不是默认推翻。

## 决策

### 1. 对齐范围与不搬清单

对齐按**行为语义**判定，不逐像素复刻：折叠档位、强制展开条件、懒加载与失效语义、点击后的信息可达性一致；形态按移动端适配（无 hover → 页脚操作常显；双列 → 单列；右侧栏 → 全屏页；键盘快捷键不做）。

明确不搬（写进 issue 的非目标）：Trajectory 视图与 Inspect 检查器、多标签/多窗口、右侧栏与宽度拖拽、快捷键体系、终端侧栏、桌面 hover 浮层与 review tab 的视图偏好。

### 2. 轮次过程折叠与展示模式

- 三层折叠：整轮（turn）→ 过程组（按事件 `step` 派生；缺 step 时退化为整轮一组）→ 单卡。
- **硬强制展开**（不可折叠）：轮次未结束、`turn/end` 的 reason.kind ∈ `aborted`/`interrupted`/`error`；底部最新组延后收起。
- **轮内有插话**：默认展开，但**允许手动折叠**（不再永久强制）；`afterAnswer` 档回答刚结束时保持展开，`onNewMessage` 档仍按轮后新消息自动收起（issue #79）。
- 四档展示模式：简洁、标准、详细、完全展开；两档收起时机：回答结束后、下次有新消息时。默认「标准」+「回答结束后」，偏好只存手机本地（不新增宿主设置端点）。

  四档策略表（与桌面 `presentation-policy.js` 同构，M1 已按此实现并验收）：

  | 档位 | foldCompletedTurns | stepGrouping | liveProcessDetail | settledReasoningPreview |
  |---|---|---|---|---|
  | 简洁 | 是 | collapsed（运行中与历史都按组） | 否（抬头只显示通用状态） | 否 |
  | 标准 | 是 | collapsed | 是（抬头显示当前工具细节） | 是 |
  | 详细 | 是 | history（运行中不分组，完成后按组） | 是 | 是 |
  | 完全展开 | 否 | none（从不分组） | 否 | 是 |

  `liveProcessDetail` 只控制运行中过程组抬头的附加细节文本，**不隐藏过程行**；单张工具卡在所有档位默认收起（桌面 `useDisclosure` 亦默认关闭），「完全展开」只影响整轮/过程组可见性；`settledReasoningPreview` 只作用于已结束的思考行，不进入整轮折叠摘要。
- 收起时机的等价实现：桌面用「底部节点 + 收起时机」决定最新一轮是否延后收起；手机实现为「下次有新消息时」档下**最新一轮保持展开**，直到下一条真人 `user/message`；「回答结束后」档完成即收起（含最新轮）。
- 过程组抬头位于过程块原位；运行中显示「正在调用工具…」，完成态显示「N 次工具调用」，**不显示用时**；整轮「已完成 · 用时 X」只出现在轮次页脚，且 aborted/interrupted/error 不显示用时。这与桌面「抬头与页脚都显示用时」是有意简化。
- 收起时机的触发 = 新的 `user/message` 进入时间线（含电脑端或另一台手机发来的）；切页、重进会话、历史回放按策略重算。手动展开只存内存，离开会话即失。
- 思维链从「钉在正文上方的聚合块」改为过程行：按事件 `seq` 与工具行交错后再按 `step` 分组，折叠态保留首行预览。最终态与**实时态**（provisional 行、落定去重、活动条分工）均已交付（issue #70）。
- 展开后单轮过程行超过 50 条时分批展示；折叠轮压成单个时间线条目不构建子项。
- 过程区视觉层级、组边界与工具卡形态见 **ADR 0028**（方案 C「章节列表」，2026-11-10）；本 ADR 只约束行为语义。

### 3. 轮末产出物契约与权限边界

- 轮末顺序：过程(折叠) → 最终回答 → 改动文件卡 → 交付文件卡 → 轮次页脚。两卡不参与整轮过程折叠，各自默认收起；无文件时不占位。
- 改动文件卡：宿主新增按轮查询的摘要端点与最小闭环 diff 端点，读取 `ctx.workspaceChanges.summary/diff`；摘要不可用（宿主重启、会话休眠、超时）时整卡不显示、不占位，负结果短 TTL 缓存。
- 交付文件卡：只下发文件名/显示名/说明与**记录坐标**，不下发主机绝对路径；点击 = 内容预览，另提供用其他应用打开/分享/保存到手机。
- 预览取数一律**按坐标**（会话 + 事件序号/轮次 + 下标），由服务端从轮末记录解析路径；**不开放任意路径读取**，也不扩大 `/api/files` 的既有语义。这与 GitLab #16 的收紧方向一致。
- 收尾正文的行内文件链接只链接本轮记录内的路径：精确路径优先，唯一 basename 次之，有歧义不链接；不猜测、不链接未记录文件。

### 4. 事件过滤与轮末信号

- `workspace/changes` 移出移动端时间线投影（历史、实时、详情三处同一规则）：它只携带轮号，对时间线没有呈现价值；移出后旧 App 不再渲染裸类型名空卡。日志与会话事实不受影响——这是「已知且不具呈现价值的事件不进入移动时间线」，不是丢弃未知事件（对照 ADR 0006）。
- 轮末信号随历史与实时下发：`/history` 响应增量 `turnTails`，实时 `turn/end` 摘要增量 `tail`；新增能力位 `turnTail`（presented/changed）与 `changes`（supported/diff），bootstrap 与 SSE hello 同判据。字段只增不改，旧 App 忽略。
- 旧插件 + 新 App：能力位缺失 → 不显示两卡/展示模式设置，并把裸 `workspace/changes` 事件归入调试可见。新插件 + 旧 App：无裸卡、无新增 UI。

### 6. 工具卡结构化（M3 Batch 1，issue #54）

- 服务端新增能力位 `capabilities.toolCards = {version:1, tools:[…]}`（bootstrap 与 SSE hello 同判据），并声明本插件实际投影的工具集合；App 以该集合逐工具决定是否使用专用卡，未列入即回退通用卡（ADR 0017）。
- `tool/call` 摘要从**原始** `data.arguments` 派生 `summary`（先解析后 clamp）：`kind`（command/file/search/web/image）+ 命令/显示路径/`sizeKb`/行范围/pattern/URL/查询/后台标志/write-edit 内联 diff（≤8 KiB，超出 `diffTruncated`）。文件路径一律经 `mobileDisplayPath` 派生，**不下发绝对路径**。
- `tool/result` 摘要从**未 clamp 的原始结果文本**解析 `exitCode`/`signal`/`stopped`（长输出的尾部标记不被 2000 字截断吃掉），search 命中数优先宿主 `meta.total`、缺失时按稳定文本句式解析，解析不到缺省。
- 三处显式口径：① `summary.stopped` 是契约外新增的可选字段（App 显示「已停止」胶囊），保留；② write 的 diff 为全新增，edit 的 `added/deleted` 为行数**近似**（old/new 行数，不作精确行级 diff 统计）；③ `resultCount` 文本兜底是启发式，宁可缺省不猜。
- 全部字段 fail-open：非法 JSON、未知工具、字段异常一律忽略并回退通用卡，不得让事件摘要/历史/SSE 出错。
- **Batch 2 已交付**（见 §8）：todo/question/skill 专用行、路径可点预览、PTC 子调用树、图库增强、实时思维链。非目标不变：Inspect / Trajectory 检查器、hover 浮层与多列布局。

### 7. 实施后补充（2026-11-08，issue #60 复核收敛）

- **路径最小披露**：轮末 summary/diff 一律由记录路径 + 会话 cwd 重新派生 display（含 binary/oversized 与 `---/+++` 标头），不直通宿主 display；presented 与 changes 共用 `recordFileId`（归一化路径的 SHA-256 前缀）作为不泄路径的逻辑身份，行内链接同 id 合并、异 id 歧义不链。
- **宿主身份**：新增 bootstrap `plugin.hostId`（持久 UUID，与口令无关）用于通知账本隔离；身份文件采用「私有候选 + 不覆盖 hard-link 单赢家」发布，损坏占位 fail-closed，访问口令不得充当宿主身份。
- **审批身份**：`approvalId` 标识一次实际审批请求（`$events` 路径 `sessionId+eventId`；接管路径 `callId+uuid`），`callId` 仅作关联；同一工具连续两次审批都必须提醒，重放仍需去重。
- **本地化与临时诊断**：过程抬头/页脚/用时走既有 `L10n`；`HOST_DIAG` 临时旁路已随上游 PR #32 移除，本 ADR 不保留该通道，后续诊断需求走正式设计。
- **实时思维链（已交付，issue #70）**：运行中按 `(turn, step)` 生成 provisional 过程行（名称/状态/首行或最新行预览），`assistant/message` 落定后由持久行替换并去重；过程块可见时活动条不重复思考文本；历史回放不受影响。

### 8. M3 Batch 2 交付（2026-11-10，issue #66/#67/#68/#69/#70/#71）

- **A 专用工具行（#66）**：`todo_write`/`ask_user_question`/`skill` 增加 `kind:"todo"/"question"/"skill"` 摘要；App 折叠行显示任务计数/问题数/技能名，展开只读清单、问题与答案（`tool/result.answers`），仍待答时提供「打开问询」入口；不在服务端执行/修改问询流程。
- **B 路径可点预览（#67）**：`tool/call.summary` 增加严格同现的 `relative`+`previewable`（cwd 相对、POSIX、realpath containment；目录/缺失/不可读/超长一律缺省）；App 二次夹取后复用会话文件预览，不新增读取端点、不改 `/m/api/files` 语义。
- **C PTC 子调用树（#68）**：`tool/ptc-dispatch-start`/`tool/ptc-dispatch` 投影为结构化事件，根工具卡下显示「N 个子调用」与缩进子行（名称/状态/安全摘要）；深度 16、按 root 最多 50、能力位 `toolCards.ptc`；不下发 arguments/content/meta/绝对路径，不做 args/结果二级展开与图片。

- **实时思维链（#70）**：见 §2/§7；流式 provisional 行、落定去重、活动条与过程行分工、历史翻页隔离。
- **视图收尾（#71）**：diff 预览整块横向滚动、固定行号列、大 diff 懒构建。
- **契约文档**：`docs/03-api.md` §6.24/§6.24.1/§6.24.2 已同步；能力位、字段与安全口径以该文档为准。

## 后果

- 手机端时间线要从「扁平消息 + 工具卡」重构成「轮次（过程组 + 页脚 + 产出物）」结构，M1 与 M2 必须串行（M2 blocked_by M1），M3 在 M1 之后。
- 轮次用时依赖新增的事件时间字段：宿主未提供时，页脚不显示用时（不猜）。
- 改动文件卡的内容是宿主内存态，宿主重启后历史轮次没有该卡；交付文件卡仍可显示（声明在事件里），但预览可能在文件被删后失败并给出明确原因。
- 移动端与桌面在「抬头是否显示用时」「点击改动行打开内容预览而非 diff」上存在有意差异，后续若要再对齐需新 ADR。
