# 0028 手机端过程折叠与工具卡视觉规范（方案 C「章节列表」）

状态：已接受（2026-11-10）。实现追踪 GitLab issue #76；行为语义沿用 ADR 0027。关联：ADR 0017（能力位/降级）、issue #73（plugin 事件可见性）、#74（图片入口）、#75（空/仅思考组）、#77（活跃会话滚动）。

## 背景

alpha.10 真机验收显示：过程折叠区在手机上「挤」——组抬头、工具标题与「收起过程」共用相近的小灰字；工具卡是白卡，思考行有浅底，纵向连续关系被切碎；组内一批工具调用缺少边界；长会话中「0 次工具调用」幽灵行、read_image 图片被多层折叠隐藏（#74/#75）进一步放大了问题。

桌面对应区域的核心信息与层级值得对齐，但手机屏幕更窄、触摸目标要求更高，不能逐像素复制。设计侧给出两个方向：

- **方向 A / 原稿**：轻量列表，组抬头 32dp，工具行平铺。
- **方向 B**：组外层软容器 + 白工具卡。
- **方案 C（采纳）**：A 的轻量平铺 + 章节化组抬头 + 「无外框」组边界导轨。

产品追加反馈明确担心「框套框」：工具调用本身已是白框时，再加组外框会形成两层边界、压缩窄屏宽度，且与轮末产出物卡争夺「产出物」视觉语言。因此否决 B 作为默认。

## 决策

### 1. 采用方案 C「章节列表」

层级与形态（逻辑 dp/sp，详细 token 见 issue #76 note 2212 的规格）：

- **L1 整轮摘要**：保留单张摘要卡（surface、1dp line、radius 14）；摘要最多两行；图片/失败 chip 在独立元信息行，不删计数。
- **L2 过程组抬头**：**最小 48dp 整行命中**，13/w600/ink，chevron 18；工具类图标 ink2、思考图标 brand；组间 8–12dp。
- **L3 过程行**：工具/思考行**平铺**（透明、无独立边框/圆角/阴影）；工具名 13/w500/ink，状态 11.5/ink2，摘要 12/ink2；思考折叠预览单行、展开正文 12/1.6 常规字形（中文不用斜体）。
- **L4 已展开详情**：仅详情区域使用 surface + radius 10 轻底；失败详情 danger@5% 轻底；不再出现整卡红色边框。
- **组边界（A 导轨）**：展开组在内容左侧 6dp 处给 **2dp 低对比导轨**，内容左移 14dp；相邻行 1dp hairline；组收起时不留导轨/空白；**不加组外框**。
- **收起过程**：顶部 8 + 1dp line + 最小 48dp，右对齐 12/ink2 脚注；不与组抬头或轮末页脚抢层级。
- **批次入口**：最小 48dp，图片 chip 独立命中；不额外加箭头，避免误读为组。

### 2. 状态与徽标

- **图片**：沿用 #74 的四层入口（整轮摘要/组抬头/工具折叠行/「显示更多」）。chip 24 高、radius 6、图标 12、数字 10.5/600/**ink**（修正 brandSoft 上的低对比），独立 32×32 命中区；点击直接开图库，不展开层、不预加载。
- **失败**：增加整轮/组的**失败计数 chip**（仅 `toolError`/`toolStatus=failed` 的工具数，不自动展开、不把工具失败等同于轮次异常）；失败工具行用 danger 图标 + ink 文本，不用整卡红边。
- **运行/停止/失败/详情加载**：运行只用真实运行态；停止沿用 `resultSummary.stopped`；详情加载失败不冒充工具失败；debug 既有失败自动展开例外保留。
- **空组/仅思考组**：沿用 #75——无可见行不渲染；reasoning-only 显示「思考 N 字」并始终有 chevron。
- **旧插件/缺字段**：全部回退平铺通用行；无图片元数据不造入口；不按版本号推断。

### 3. 布局与无障碍

- 宽屏：徽标在组头右栏；内容宽 <328dp（屏宽 <360）或 textScale>1.2 时，徽标移到文案下方一行，组头自然增高，不覆盖主行点击区。
- 图片计数自然扩宽，禁止硬编码宽度或改用 99+；长工具名/命令/路径用既有展开可达，不用缩字号或隐藏计数解决窄屏。
- 过程区正文/状态不再使用 `ink3`；可读文字目标 ≥4.5:1，交互图标 ≥3:1；导轨只是辅助归属，不充当唯一焦点或按钮轮廓。
- 内置语义：组头/收起是 button+expanded；图片入口独立节点「查看 N 张图片」；失败 chip 是状态不是按钮。

### 4. 明确不改的行为

四档展示模式、两档收起时机、强制展开三条件、50 行分批、单卡默认收起、手动展开覆盖、provisional 思考插入/落定去重、路径点击/打开问询、PTC 子树、旧插件降级——全部沿用 ADR 0027。**「完全展开」仍只指整轮/过程组可见性，不是单卡全开。**

## 备选与否决理由

- **B 外框 + 白工具卡**：形成框套框、压缩窄屏有效宽度、与轮末两卡视觉冲突；仅作为对照稿保留。
- **仅短分隔条**：视觉最轻，但长组滚动到中段时归属不明确；导轨同时解决边界与归属，成本仅 2dp。
- **32dp 组头**：触摸目标偏小、层级弱；接受每组 +16dp（四组约 +64dp）换可读性与「大方」。

## 后果

- 过程区高度增加（四组约 +64dp），但层级更清楚、触摸更稳；长内容仍由滚动/折叠/分批控制。
- 不引入新设计系统：全部复用 `DshColors`/`DshTheme`；实施集中在 `chat_screen.dart` 的 `_ProcessSummaryRow`/`_ProcessGroupHeader`/`_CollapseProcessRow`/`_ToolActivityCard` 过程区变体与 `_ReasoningProcessRow`。
- 需要新增/更新 widget 回归：390/320、浅/深、textScale 1/1.3/1.5、双徽标、三位数图片、长工具名/命令/路径、四档×两时机、强制展开、50/51/100/101 行、旧插件降级、图片四层入口、空/仅思考组。
- 真机 before/after 截图与录屏作为 #76 验收证据；设计稿（mock）不能替代真机通过。
- 后续若调整 token/边界，必须先改本 ADR；行为语义仍以 ADR 0027 为准。
