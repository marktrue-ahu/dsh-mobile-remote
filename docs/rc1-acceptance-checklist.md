## 验证方法

- 以现有手机 HTTP API 和 SSE 为主要自动化测试入口，同一套行为断言分别验证 DSH 0.1.1-rc.2 和 0.1.2-rc.1。
- 以现有发布版 Android App 验证用户操作、图片显示、问询审批和重连；电脑设置页另做真实界面验证。
- 模拟宿主或外部服务用于可重复的超时、错误和竞争测试，不能替代真实宿主验收。
- 使用独立测试 profile、临时工作区及专用会话。测试会发送消息、修改配置和创建文件；不直接复用用户正在工作的会话。
- 每个用例记录版本、环境、步骤、预期、实际结果及证据。状态区分通过、失败、未验证和阻塞；跳过不计为通过。

## 外部条件

- 视觉模型、余额接口和第三方推送需要对应测试条件；缺少条件时标记未验证或阻塞，不能用模拟结果宣称真实链路已通过。
- 推送自动化先使用本地接收端验证协议与内容；向真实外部渠道投递前确认专用测试目标。
- 本次验证当前分支的已有功能；其他功能分支中新加的能力不自动纳入本清单。

## 现有 e2e-check.mjs 的定位

这是仓库已有的 Node.js 手工辅助检查脚本，通过 HTTP 连接一个已运行的插件实例，不会启动 DSH，也不会操作 Android 界面。

它连接 SSE、读取 bootstrap、向返回的第一个 agent 发出固定自检消息、打印事件类型，最后尝试错误口令触发限流。无 agent 时跳过发送。缺少事件或限流未触发时主要打印信息，没有完整的失败退出判定。

运行会触发真实会话消息，并可能导致测试来源 IP 暂时被限流；因此只能作为现有测试入口的参考，不能直接作为完整验收套件。目前未执行该脚本。
