# DSH 0.1.5-rc.2 适配需求讨论

状态：grill-with-docs 已完成最终确认，to-spec 已发布。本轮未开始代码实现。

Spec：[GitHub Issue #7](https://github.com/marktrue-ahu/dsh-mobile-remote/issues/7)，标签 `ready-for-agent`；[本地正文](specs/dsh-0.1.5-rc2-compatibility.md)。

基线：从 `main` 切出 `feature/dsh-0.1.5-rc2-compat`。上游目标为 DSH **0.1.5-rc.2**。

> 说明：最初设想的基线是 `feature/app-git-management`（该分支含有既存的适配层、验收清单与三条验证脚本）。确认阶段查证后发现 `main` 与 `feature/app-git-management` 的兼容性实现已经分叉，最终决定从 `main` 切出，并只从 `feature/app-git-management` 搬运**文档资产**（验收清单与验证记录），不搬运任何 Git 管理代码。

## 已确认

### 目标与范围

- 只适配上游当前最新发行版 DSH 0.1.5-rc.2，即当前 Typert 代际（依赖范围写作 `^0.1.5-rc.2`），不支持更早代际。
- 不为更早代际保留适配保证；仍为旧代宿主保留的交互通道**保持可用**，但输出显式弃用日志提示升级内核。
- 不改变插件与 App 的版本号，只把插件版本追平到已发布版本。版本号管理属于上游仓库作者，本 fork 不自行发版。

### 兼容性判定

- 判定改为**能力探测**，拆为三个互相独立的探测项：新代 Remote 调用入口、Remote 事件桥入口、冷会话恢复入口。
- 不把「能调用」与「能收事件」合并成单一布尔值——旧一代宿主恰有「有调用方法但无事件流面」的组合，合并后会产生「宣称新代但事件桥未启动」的不一致结论。
- 宿主版本号只用于诊断展示与升级提示，**不参与功能门控**。
- 插件不拒绝加载在范围外的宿主；能力缺失由功能级明确错误与诊断上报承担。
- 不采用启动期硬版本拦截。

### 诊断与提示

- 环境诊断新增宿主节：宿主版本号 + 三项能力布尔值 + 是否受支持。
- App 环境诊断页新增一行电脑端兼容状态。
- 问询/审批能力缺失时，相关操作失败提示**额外带升级指引**（唯一会让使用者彻底无法继续的场景）。

### 行为修正

- 发送请求的幂等标识改为**无条件传递**：新内核请求参数校验为严格模式，缺失该字段会导致投递被直接拒绝，而非仅失去幂等保护。
- 删除会话标识的前缀剥离逻辑：当前代内核的会话标识不含该前缀，该剥离从未生效。
- 内核新增的请求幂等层与插件自建回执层**两层都保留**并注释分层职责：内核负责不重复执行同一请求，插件负责传输层中断后回答「是否已送达」。
- 队列视图改为订阅内核**会话内队列变更事件**，替代依赖新代事件桥转发队列帧的做法。该事件在上一代与当前代均存在且载荷一致。

### 代码清理

- 删除三处已证实不可达的路径：旧代一次性 Host Remote 调用封装、依赖已停止发布的交互服务封装、以及在内核端点表中不存在的调用映射。
- 三者都依赖同一个已消失前提（旧代宿主），保留即累积不可维护的死代码。

### 文档与验收

- 更正既有文档中的错误结论：仓库把「插件上下文隔离导致无法读取兄弟插件服务」记为设计原因，实际原因是服务激活时间点晚于插件装配；上游官方指引明确可选服务应直接读取。
- 兼容性文档中关于旧代支持的三节改写为单代口径。
- 验收沿用既有清单结构（T01–T19），宿主替换为 0.1.5-rc.2，清除旧代宿主行，并补充本次新增项：升级提示、能力上报、队列帧同步、受支持范围判定。
- 未被验证的验收项**显式记录为未验证**，不留空白。
- 新增一条架构决策记录，记录「只支持当前内核代际」与「以能力探测而非版本判断判定兼容」两项决定，含选择理由与放弃旧代适配的代价。
- 变更日志新增明确标注为**本地**的条目记录本次适配点，不改动上游版本条目。

### 测试

- 唯一测试 seam：**手机 HTTP 接口**。既有验收清单已把它定为主要自动化测试入口，本次不引入新 seam。

### 发版门槛

- 允许增量版发布，发版说明如实标注已验证范围。
- 本次完成后**仍不得对外宣称「完整兼容」**，只标注在哪一代宿主、哪种形态、哪个平台上实测通过。

## 评审中更正的既有事实

以下四点在本次评审中被查证推翻，是决策依据的一部分，务必随实现一并更正或消除：

1. **`typertGateway` 不是代际标记**。0.1.1-rc.2 也提供该服务且同样具备 `invoke()`；可靠的新代标记是事件流面与远端事件注册方法。现有以 `invoke` 存在性为准的判定会在旧代上误判为「新代」，导致诊断宣称新代而事件桥静默不启动。

2. **「`ctx.get` 看不到兄弟插件服务」是误判**。真实原因是服务激活时间点晚于插件装配，与上下文隔离无关；上游官方插件指引明确可选服务应当直接读取。仓库现有文档据此推导出的实现方式需要更正。

3. **会话标识不含前缀**。当前代内核的会话标识形如 `session-<uuid>`，全库没有冒号前缀约定，既有的前缀剥离是永不命中的空操作。

4. **发送幂等标识在目标版本是必填**。缺失会被网关以参数校验失败直接拒绝投递；该字段同时是内核新增幂等层的依据，而该幂等层在上一代内核中并不存在。

另有一条实践性提醒：profile 的依赖副本会镜像本次安装的依赖闭包，且**只增不删**，升级后会留下指向已不存在包的断链。因此判断某个内核包是否存在时，必须探测其清单文件而不是目录存在性。

## 与既有决策的关系

本轮的「收敛为单代」与上一轮 `dsh-0.1.2-rc1-compatibility` 的「双版本支持」是**方向相反的决策**，而非补充。上一轮的领域术语「双版本兼容」因此在术语表中被删除，不再新增替代词条——单代世界里「代际」不构成一个真实存在的领域区分，其纪律写入架构决策记录即可。
