# 10 DSH 0.1.5-rc.2 验收清单

> 关联：[Issue #7](https://github.com/marktrue-ahu/dsh-mobile-remote/issues/7)、[spec](specs/dsh-0.1.5-rc2-compatibility.md)、[ADR 0001](adr/0001-current-dsh-generation-only.md)、[09-compatibility](09-compatibility.md)
> 状态口径：✅ 已实测通过 ｜ ◐ 部分验证 ｜ ⬜ 未验证 ｜ ⛔ 已知阻塞

## 1. 范围与纪律

- **受支持宿主**：`>=0.1.5-rc.2 <0.2.0`。旧代际（0.1.1-rc.2 / 0.1.2-rc.1）不在验收范围内，其行为只要求「不崩、明确报错」。
- **唯一测试 seam**：手机 HTTP 接口（`/m/api/*`）。所有断言都在这一层观察，不直接断言插件内部函数。
- **纪律**：
  - 缺环境的项记录为 ⬜ **未验证**，不留空白，也**不得**由其他环境或其他内核版本的既有证据平移推定。
  - 逐项验收完成前**不得对外宣称「完整兼容」**。
  - 目录浏览类用例需同时覆盖 Windows 与 WSL/Linux 路径形态。
- **自动化入口**：`tools/e2e-check.mjs`（需 `DSH_MOBILE_TOKEN`）覆盖核心 API 链路；`tools/verify-host-compat.mjs` 覆盖宿主版本范围判定；`tools/verify-image-sniff.mjs`、`verify-64k-fix.mjs`、`verify-413-precheck.mjs`、`wsl-path-check.mjs`、`hotfix07-unit-check.mjs` 为模块级回归。
- **前置**：插件已安装并启用；访问口令启用（`authToken`，下文 `<TOKEN>`）；桌面端 LAN 桥监听（`lanBridge.enabled: true`，默认 `0.0.0.0:3080`）。

## 5. 结论

- 本清单的 T01–T23 在 `0.1.5-rc.2 × Desktop/Web` 两格上**尚未执行**。当前只有模块级回归（`tools/verify-host-compat.mjs` 等）通过，不能替代宿主实测。
- 在 T01–T23 逐项给出证据之前，**不得对外宣称「完整兼容」**；`docs/09-compatibility.md` 的受支持范围只表示「代码层面对该代际做了适配」，不等于已验收。
